# 整屋清扫复测：茶几通道扩大

日期：2026-11-12  
平台：Ubuntu 24.04 VM，ROS 2 Jazzy，Gazebo Harmonic 8  
样本：1 轮有效整屋任务

## 输入与运行

- Gazebo 世界：`inputs/living_room.world`。茶几 `TableMarble` 的 y 位姿由 `0.10 m` 改为 `0.65 m`，向电视柜方向移动 `0.55 m`。
- 导航地图：`inputs/living_room.pgm`、`inputs/living_room.yaml`。Nav2 日志确认加载 100 x 98、0.05 m/cell 的地图；世界和 PGM 哈希与 VM 本轮启动所用文件一致。
- 地图目标清扫范围：5,450 个真值目标栅格；业务目标覆盖率 90%。
- 保持 VM 中既有机器人、Nav2 与清扫参数；运行参数和完整命令见 `living-room-official.D2Bdag/run-benchmark.sh`。
- 完整原始结果、逐位姿比较、覆盖网格与启动日志见 `living-room-official.D2Bdag/living_room/run-1/`。

| 指标 | 本轮结果 |
| --- | ---: |
| Gazebo 独立真值覆盖率 | 92.24% |
| 运行时估算覆盖率 | 90.46% |
| 真值与估算差 | 真值高 1.78 个百分点 |

| Action 状态 | `SUCCEEDED`（状态码 4） |
| 墙钟耗时 / 仿真时间 | 653.03 s / 408.37 s |

任务在真值覆盖率 90.13%（42.02 m）时已跨过业务门槛；随后继续补扫到 92.24%，终止里程增加 3.83 m。最终覆盖率达标，但全程效率未达 80%，所以联合性能项 `performance_passed` 为 false。

Action 结果原因是“达到覆盖目标，但补扫预算用完前未达到完成余量”，并附有 16 个跳过航点。默认完成余量为 1 个百分点：运行时覆盖率为 90.46%，低于 91% 余量线，但仍达到 90% 业务目标，因此预算耗尽时 Action 成功。Gazebo 真值只用于离线评估，没有参与任务决策。

## 有效性与限制

- 本轮是真实 Gazebo 整屋仿真，世界文件和 Nav2 地图均为茶几移动后的版本；不是仅验证通道通过的旧样本。
- 只有 1 轮，不能据此声称跨轮稳定性或给出统计结论。
- VM 构建 overlay 位于 `/home/xbs/robot_sweeper/ros2_ws/install`。VM 的 `cleaning_task_manager.cpp` 与 Mac 工作区版本有一处源码差异：VM 增加了“整轮补扫目标均被实时代价地图阻挡时，下轮规划排除延后目标”的逻辑。本轮日志没有出现该分支的重规划事件；其余完成判定头文件哈希一致。故本结果应视为 VM 当前 overlay 的实测，不能宣称为与 Mac 源码字节完全一致的复现。
- 本轮没有重新执行全包构建或单元测试；当前没有遗留 Gazebo / ROS launch / benchmark 进程。
